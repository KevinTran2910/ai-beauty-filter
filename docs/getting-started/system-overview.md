# System Overview

## System Goal

This system packages the native AI Beauty Filter SDK for use inside an iOS
React Native demo app. The demo focuses on two workflows:

- **Static image processing:** pick an image from the photo library, decode it,
  run the beauty pipeline, and render the result into a native view.
- **Real-time camera processing:** capture frames from the front camera, run face
  detection and the beauty pipeline, and display the processed output live.

## Main Components

```text
ios/
├── bootstrap.sh
├── BeautyFilterSDK.podspec
├── native-bridge/
├── prebuilt-sdk/ios/
├── app-template/
└── BeautyFilterDemo/        # generated by bootstrap.sh
```

### `bootstrap.sh`

Creates or updates the demo app. Main responsibilities:

- Runs the React Native CLI `init BeautyFilterDemo`.
- Installs the npm dependencies the demo needs.
- Overlays `app-template/App.tsx` and `app-template/src/index.ts` into the
  generated app.
- Adds the local `BeautyFilterSDK` pod to `BeautyFilterDemo/ios/Podfile`.
- Adds camera and photo-library usage descriptions to `Info.plist`.
- Runs `pod install`.

The generated `BeautyFilterDemo/` is reproducible and is not the canonical SDK
source; it can be recreated at any time.

### `BeautyFilterSDK.podspec`

This local CocoaPod brings the native bridge and prebuilt SDK into the app. The
pod includes:

- ObjC++ bridge source from `native-bridge/**/*.{h,mm}`.
- `prebuilt-sdk/ios/BeautyFilter.xcframework`.
- Runtime resources from `prebuilt-sdk/ios/res` and `prebuilt-sdk/ios/models`.
- Device-build links for `MNN.framework` and `libmars-face-kit.a`.
- A `React-Core` dependency for `RCTViewManager` and native module headers.

For device builds the podspec sets:

- `GPUPIXEL_ENABLE_FACE_DETECTOR=1`
- Links for `MNN`, `CoreML`, `Metal`, and `mars-face-kit`

Simulator builds do not link MNN or mars because those binaries only ship a
device slice in the current SDK package.

### `prebuilt-sdk/ios/`

Contains the already-built native SDK. This repository does not rebuild the C++
engine. Important contents:

- `BeautyFilter.xcframework`: the packaged GPUPixel engine (device + simulator
  slices).
- `MNN.framework`: AI framework used by face detection on device.
- `libmars-face-kit.a`: landmark/face-kit library used on device.
- `include/`: GPUPixel headers.
- `res/`: lookup tables and runtime image resources.
- `models/`: face-detection models.

Do not remove or restructure `res/` and `models/` unless the native loading code
is updated. The bridge calls
`GPUPixel::SetResourceRoot([[NSBundle mainBundle] resourcePath])` and resolves
resources relative to the app bundle.

### `native-bridge/`

The ObjC++ bridge connecting React Native to the C++ engine:

- `GPUPixelImageView.{h,mm}`: native view for static-image processing.
- `GPUPixelImageViewManager.{h,mm}`: exposes `GPUPixelImageView` to React Native.
- `GPUPixelCameraView.{h,mm}`: native view for real-time camera processing.
- `GPUPixelViewManager.{h,mm}`: exposes `GPUPixelCameraView` to React Native.
- `GPUPixelModule.{h,mm}`: older imperative native module for start/stop camera
  and parameter updates. The current demo prefers prop-driven control because it
  is more stable with React Native New Architecture interop.

### `app-template/`

JS/TS files copied into `BeautyFilterDemo` on each bootstrap run:

- `App.tsx`: the demo screen with Image/Camera modes, image picker, and sliders.
- `src/index.ts`: TypeScript wrappers for the native components.

## Static Image Flow

1. JavaScript calls `launchImageLibrary` to obtain an `imageUri`.
2. `App.tsx` renders `GPUPixelImageView` with `imageUri` and filter parameters.
3. `GPUPixelImageViewManager` maps React Native props to ObjC++ setters.
4. `GPUPixelImageView` decodes the image into RGBA and normalizes orientation.
5. The view initializes the native pipeline once it has valid bounds.
6. On device builds with face detection enabled, native code detects landmarks.
7. The pipeline processes the frame and renders into `SinkView`.

Current pipeline:

```text
SourceRawData -> BlusherFilter -> FaceReshapeFilter -> BeautyFaceFilter -> SinkView
```

Parameter mapping:

| JS prop | UI range | Native mapping |
| --- | ---: | --- |
| `smoothing` | 0-10 | `SetBlurAlpha(value / 10)` |
| `whitening` | 0-10 | `SetWhite(value / 20)` |
| `faceSlim` | 0-10 | `SetFaceSlimLevel(value / 200)` |
| `eyeEnlarge` | 0-10 | `SetEyeZoomLevel(value / 100)` |
| `blusher` | 0-10 | `SetBlendLevel(value / 10)` |

## Real-Time Camera Flow

1. JavaScript renders `GPUPixelCameraView`.
2. The native view starts the camera once it is attached to a window and has
   valid bounds.
3. `AVCaptureSession` uses the front camera, preset `1280x720`, and BGRA output.
4. The capture delegate receives each frame on a serial queue.
5. On device builds with face detection enabled, each frame is analyzed for
   landmarks in video mode.
6. The BGRA frame is sent into `SourceRawData` and rendered through the pipeline.
7. The camera stops automatically when the view is removed from the window.

Camera mode is not available on the iOS Simulator.

## Simulator vs Device

| Capability | Simulator | Physical iPhone |
| --- | --- | --- |
| Skin smoothing | Yes | Yes |
| Whitening | Yes | Yes |
| Face landmarks | No | Yes |
| Face slimming | No | Yes |
| Eye enlargement | No | Yes |
| Landmark-based blush | No | Yes |
| Real-time camera | No | Yes |

Reason: `MNN.framework` and `libmars-face-kit.a` only provide device slices, so
simulator builds do not enable `GPUPIXEL_ENABLE_FACE_DETECTOR`.
